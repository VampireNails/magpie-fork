- Baseline: `400d392a89c6818d16d87d36333aabfe1201f143`, source `D:/tmp/magpie-c3-integration`, clean status at inspection. Separate worktree `D:/tmp/magpie-hermes-restore`, branch `fix/hermes-restore-fidelity`.
- Environment: Windows 10 Pro, Windows amd64, Git 2.54.0.windows.1, Go 1.27.3. Tests use synthetic values and test temporary homes; no real Hermes instance, credentials, service or network call.
- PRD v3.3 sections 4.3, 5.2 and acceptance row 5 require restoration of corresponding configuration, not byte-for-byte restoration. Keeping changes to an unrelated anchor means a restored alias resolves to its current value: the PRD does not settle this conflict. This implementation preserves that unrelated change. Nested external aliases are rejected before a managed write instead of risking an unrecoverable baseline.
- Reproduction on baseline: `go test -tags nogui ./internal/agent -run '^TestManagedHermesAliasLifecycle$' -count=1 -v` failed at `disconnect: managed: restore incomplete` after successful `Agent.Apply`; a YAML alias serialized without its anchor cannot be parsed as a standalone value. This is a substantive failure to restore the managed model.
- The CRLF fixture with header, key, value, whole-line and inline comments, original model/provider fields and a later `agent.max_turns` edit was exercised through `Agent.Apply` and `Agent.Disconnect`. Values and listed comments survived, and max_turns was 9. The output had mixed LF/CRLF, so it was not byte-identical. The separate alias fixture retained alias semantics but also observed a duplicate `# shared model` on an unrelated line; comment placement/duplication is not fully faithful and whether that violates the PRD needs a product decision. No byte-identity requirement is inferred.
- Failure coverage: missing alias anchor leaves the journal pending; restoring the anchor allows retry. Nested references to an outside anchor fail before the first config write. Existing managed Hermes tests cover malformed files, retries, .env and hardlinks. Older journals lacking alias metadata remain pending for this case.
