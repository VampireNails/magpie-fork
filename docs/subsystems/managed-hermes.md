# Managed Hermes restoration

The local Hermes adapter uses the managed session journal and does not change remote server state. `HermesManagedRoot` and `HermesManagedInitialTargets` resolve the native active profile; `HermesManagedAdapter` validates journal targets within that root. During a managed operation, `WithManagedHermes` constructs an operation-scoped native connector. The integration must hold its per-agent operation guard, invoke it synchronously inside `ManagedSession.BeforeManagedWrite`, and discard both connector and scope before the callback returns. The scope must not cross goroutines. Do not call the public managed method or public Disconnect from inside this callback.

The adapter records each affected profile's model subtree, `providers.magpie`, and `agent.reasoning_effort`. The native provider construction captures each actual environment variable immediately before creating or editing its profile's `.env`; capture failure stops that write. Initial profile discovery is repeated before each operation, and later profiles are added in the same generation. Malformed or unreadable configuration stops the operation. Restore applies captured regions without testing current values, then the store finalizes file existence and mode only after all regions have succeeded. Ordinary unrelated fields and variables are retained; a restored original scalar parent conflicting with later unrelated children fails for retry rather than discarding the children. Standalone comments are retained through removal of a YAML node.

The managed restore intentionally does not invoke native Disconnect: it would make additional writes to profiles, including copying an unrelated provider. S8 must prevent and drain concurrent native writes before restore and must manage Hermes-specific native bookkeeping without replacing shared stash or applied files. The adapter alone does not guard public Apply, ConnectHow, Disconnect, or SyncCatalog, start a service, or establish offline behavior. Existing Hermes processes may keep cached configuration until restarted; no process is killed by this adapter.

Tests: `go test -tags nogui ./internal/agent -run '^TestManagedHermes'` plus `TestHermes` regression and race on the target OS. Tests use isolated homes, synthetic keys and no external requests. Full product offline and reconnect acceptance requires the integrated system and real agent processes.

Managed dotenv snapshots retain each target assignment and position anchors for the intervening original records. Variable anchors identify names rather than values, so unrelated value edits and new records survive. An ambiguous, removed, or reordered anchor stops restoration for retry. Older unanchored assignment-line snapshots cannot establish their original positions and remain pending; snapshots made before assignment-line capture cannot recover comments they never stored.

YAML capture records the resolved value of aliases, including nested external references. On restore, a whole-value or parent alias is kept only when a unique current anchor resolves to the captured value and restoring it is safe; otherwise the saved value is materialized without changing that anchor. Nested aliases are materialized. A snapshot whose expansion exceeds the capture limit is rejected before the managed write. Old alias-only journals lack the original value and stay pending rather than silently rebinding to a changed anchor. Restoring a scalar or alias parent still fails for retry if it would discard unrelated children, and YAML validation prevents a replacement from leaving other aliases dangling. Formatting need not be byte-identical.
